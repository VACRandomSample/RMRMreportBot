# RMRP Report Bot

Telegram-бот сохраняет скриншоты отчётов на Яндекс.Диск: наказания, помощь в МП,
мероприятия и события с началом и окончанием. Часовой пояс отчётов — Москва.

## Запуск

Требуется Node.js **22.13.0 или новее** (встроенный `node:sqlite`).

```sh
npm ci --ignore-scripts --no-audit --no-fund
cp .env.example .env
# Заполните TOKEN_BOT и реквизиты OAuth приложения Яндекса в .env.
node src/index.js
```

Запускайте **один процесс** бота. Путь SQLite по умолчанию — `data/state.sqlite`;
его можно изменить переменной `STATE_DB_PATH`. Второй процесс с той же базой
отклоняется. После аварийного завершения оставшаяся блокировка снимается при
следующем запуске, если прежний PID больше не существует. При повреждённой
блокировке сначала убедитесь, что бот остановлен, затем удалите `state.sqlite.lock`.

Сохраняйте `.env`, `user_settings.json`, папки `data/` и `photos/` между обновлениями
и перезапусками контейнера. В SQLite хранятся текущий диалог, события, очередь,
номера и история подтверждённых загрузок. Токены пользователей остаются в
`user_settings.json`; эти файлы исключены из Git. Для резервной копии остановите
бота и скопируйте эти файлы и папки целиком, включая SQLite WAL, если он существует.

## Как отправлять отчёты

1. Отправьте фото или изображение как документ. Для документов поддерживаются
   JPG, PNG, GIF и WebP; сохраняется исходное расширение по MIME-типу.
2. При необходимости до выбора сохранения задайте фактическое время скриншота:
   `/time 14.10.2026 23:59` (МСК). По умолчанию используется время сообщения Telegram;
   дата внутри изображения автоматически не распознаётся.
3. Выберите категорию и этап. Если незавершённых событий несколько, для окончания
   появится список с номером, неделей и категорией, по восемь событий на страницу.
4. Сообщение «добавлено в очередь» означает, что задание сохранено локально.
   Отдельное «Сохранено» приходит после проверки загрузки на Яндекс.Диске.

Окончание сохраняется в папку начала с тем же номером, даже после полуночи,
смены недели, года, дневной/ночной категории или базового пути. Можно начать
несколько событий одного типа: они не заменяют друг друга. Пока идёт выбор
категории для одного фото, следующее фото не принимается; завершите выбор или
отмените его, затем отправьте следующее. Старые кнопки не могут управлять новым фото.

## Команды

| Команда | Назначение |
|---|---|
| `/auth`, `/code КОД` | Подключить Яндекс.Диск |
| `/settings`, `/setpath ПУТЬ` | Настройки и базовая папка |
| `/time ДД.ММ.ГГГГ ЧЧ:ММ` | Время текущего фото по Москве |
| `/pending`, `/pending_mp` | Все сохранённые незавершённые события независимо от недели и времени суток |
| `/sync_events` | Найти начала без окончания во всех папках недель на диске и восстановить записи |
| `/uploads` | Задания, ожидающие подтверждения, и причины ошибок |
| `/retry_uploads` | Возобновить остановленные после ошибок задания |
| `/weekly`, `/weekly previous` | Сводка за текущую/предыдущую неделю и ссылки на папки |
| `/reminders on`, `/reminders off` | Включить/отключить напоминания в личном чате |
| `/reset_wizard` | Отменить текущий выбор категории; отправленное в очередь задание не отменяется |
| `/clear_pending confirm` | Убрать незавершённые события из списка; файлы на диске не удаляются, активные/ошибочные загрузки сохраняются |

Напоминания по умолчанию выключены. После включения первое отправляется не раньше
двух часов с начала, затем не чаще раза в сутки. Кнопка «Добавить конец» выбирает
событие для следующего фото. Если начало ещё в очереди или окончание уже принято,
напоминание не отправляется. Время проверки — раз в час.

Сводка считает подтверждённые загрузки этой версии. Восстановленные с диска старые
незавершённые события также видны; полная история завершённых отчётов прежней
версии автоматически не импортируется. Команда `/sync_events` просматривает все
папки недель, поэтому на большом архиве может выполняться долго. При общей папке
Яндекс.Диска она не может определить автора старого скриншота: используйте отдельный
базовый путь для каждого пользователя или запускайте восстановление владельцем папки.

## Надёжность загрузки

Очередь проверяется каждые 15 секунд. При сетевой ошибке выполняется до пяти попыток
с увеличивающимся интервалом; после этого задание остаётся с ошибкой до
`/retry_uploads`. Окончание ждёт подтверждения загрузки своего начала. Локальные
файлы очереди (включая ошибки) и текущего диалога не удаляются автоматической очисткой.
Подтверждённые локальные файлы удаляются, остальные неиспользуемые файлы — через час.

Запись на Яндекс.Диск выполняется с `overwrite=false`. При повторе после потери
ответа бот сравнивает размер и MD5 существующего файла с локальными байтами:
совпадение подтверждает загрузку, другое содержимое останавливает задание с
конфликтом. Конфликты не исправляются перезаписью. В этом случае проверьте файл
на диске, устраните конфликт имени и выполните `/retry_uploads`.

SQLite хранит абсолютные локальные пути файлов. При переносе установки сохраните
тот же путь к проекту либо перенесите файлы и корректно обновите пути в состоянии
до запуска. Удаление папки `photos/` вручную лишит очередь исходных байтов.

## Обновление с прежней версии

1. Остановите старый бот. Сделайте резервную копию `.env`, `user_settings.json` и `photos/`.
2. Установите Node.js 22.13+ и обновите код. Выполните `npm ci --ignore-scripts --no-audit --no-fund`.
3. Запустите один процесс через `node src/index.js` и проверьте `/test`.
4. Выполните `/sync_events` для восстановления начал, которые старый бот уже сохранил
   на диск. Несохранённые диалоги старой версии хранились в памяти и не импортируются:
   такие фото следует отправить повторно.
5. Включите напоминания при необходимости: `/reminders on`.

`original-bot.js` оставлен как историческая версия. Рабочая точка входа — `src/index.js`.

## Проверка

```sh
npm test
```

Тесты используют временные SQLite-базы и имитацию Telegram/Яндекс.Диска;
реальные сообщения и файлы в облако не отправляются. GitHub Actions запускает
тесты на Node.js 22 и 24.
